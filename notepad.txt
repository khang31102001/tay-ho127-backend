## TASK 2: Setup môi trường Local Development trên VS Code

### Mục tiêu
Thiết lập máy Windows hiện tại để có thể build, chạy và debug Backend trực tiếp bằng VS Code, KHÔNG dùng Docker vì Docker đang gây lag máy.

Sau khi hoàn thành, tôi phải có thể:
- mở source bằng VS Code;
- restore/build source;
- chạy Backend local;
- mở Swagger để test API/module;
- debug, chỉnh sửa code và chạy lại dễ dàng.

### Yêu cầu thực hiện

1. Đọc source trước để xác định chính xác:
   - phiên bản .NET SDK cần dùng (`global.json`, `.csproj`);
   - database/provider đang sử dụng;
   - EF Core version;
   - các dependency/tool cần thiết;
   - cấu hình Development hiện tại.

2. Kiểm tra máy tôi đã có gì và chỉ cài những thứ còn thiếu, ví dụ:
   - đúng phiên bản .NET SDK;
   - VS Code C# / C# Dev Kit;
   - `dotnet-ef` đúng version nếu project sử dụng migration;
   - PostgreSQL / PostgreSQL client nếu thực sự cần;
   - các CLI/tool khác mà source yêu cầu.

Có thể dùng terminal để cài trực tiếp nếu an toàn.

3. KHÔNG yêu cầu Docker để chạy local.

4. Chuẩn hóa cấu hình Development:
   - `appsettings.Development.json`;
   - Connection String;
   - JWT/config cần thiết;
   - environment variables / User Secrets nếu cần.

Không hard-code secret vào source và không làm thay đổi Production config.

5. Sau khi setup xong, tự chạy kiểm tra:
   `dotnet --info`
   `dotnet restore`
   `dotnet build`
   `dotnet run`

6. Nếu build/run lỗi:
   đọc log → xác định root cause → sửa hoặc bổ sung môi trường → chạy lại cho đến khi Backend chạy được.

7. Kiểm tra Swagger thực tế:
   - xác định URL/port;
   - xác nhận Swagger load thành công;
   - thử ít nhất một API phù hợp để xác nhận application hoạt động.

8. Nếu database cần migration/seed, kiểm tra kỹ trước khi chạy.
KHÔNG chạy migration destructive hoặc thay đổi database Production/Render ngoài ý muốn.

### Kết quả cuối cùng
Báo cáo ngắn cho tôi:
- Đã cài những công cụ nào + version.
- Công cụ nào đã có sẵn.
- File/config nào đã chỉnh.
- Lệnh chuẩn để lần sau tôi tự chạy project.
- URL Swagger local.
- Cách Run/Debug bằng VS Code.
- Build: PASS/FAIL.
- Backend local: PASS/FAIL.
- Swagger: PASS/FAIL.

Chỉ kết luận hoàn thành khi tôi có thể chạy Backend + Swagger local mà không cần Docker.

## TASK 3: Diagnose Laptop RAM Overflow / Black Screen

### Mục tiêu
Kiểm tra laptop Windows hiện tại để xác định nguyên nhân máy bị tăng RAM bất thường, sau đó đen màn hình và chỉ có thể reset máy mới hoạt động lại.

### Yêu cầu
1. Chỉ DIAGNOSE trước, chưa tự ý xóa dữ liệu, uninstall phần mềm, chỉnh Registry/BIOS hoặc thay đổi cấu hình hệ thống nguy hiểm.

2. Thu thập và phân tích:
- Tổng RAM, RAM usage, Commit/Virtual Memory và Pagefile.
- Process/service đang chiếm RAM nhiều nhất.
- Memory leak hoặc process có RAM tăng liên tục.
- Docker Desktop / WSL2 / `vmmem`.
- VS Code, Claude/Node.js, browser và các development process.
- GPU RAM/driver và khả năng GPU driver gây black screen.
- Windows Event Viewer: System/Application.
- Reliability Monitor.
- WHEA / Kernel-Power / Display driver / Out-of-memory errors.
- Crash dump/minidump nếu có.
- Startup/background applications.

3. Nếu cần, dùng PowerShell/CMD để lấy số liệu và tạo log phục vụ phân tích.

4. Phân biệt rõ nguyên nhân có khả năng thuộc:
- RAM vật lý thiếu/lỗi.
- Memory leak phần mềm.
- Pagefile cấu hình sai/thiếu.
- Docker/WSL chiếm RAM.
- GPU/driver.
- Windows/system issue.
- Phần cứng khác.

5. Xếp hạng Top 3 nguyên nhân có khả năng nhất dựa trên bằng chứng thực tế.

6. Sau khi xác định root cause, đề xuất cách xử lý theo thứ tự:
   Fix an toàn → kiểm tra lại → chỉ thực hiện thay đổi lớn khi thật sự cần.

7. Sau khi fix, chạy lại kiểm tra RAM và theo dõi để xác nhận vấn đề đã được cải thiện.

### Báo cáo cuối
Cho tôi bảng ngắn gồm:
- Triệu chứng.
- Bằng chứng/log tìm được.
- Root cause hoặc nguyên nhân nghi ngờ.
- Mức độ tin cậy.
- Cách khắc phục đề xuất.
- Những thay đổi đã thực hiện.
- Trạng thái sau khi kiểm tra lại.

Không kết luận đơn giản là “thiếu RAM”; phải tìm nguyên nhân vì sao RAM tăng và vì sao hệ thống chuyển sang black screen.
